In this chapter, you'll install the Enonic CLI, start a local XP sandbox, and create the app that will hold your content types.
It takes a few minutes, and everything you install here is used in every later chapter.

== Install the CLI

Enonic provides a Command Line Interface (CLI) for working with XP. It manages local XP instances, creates projects from starters, and builds and deploys your apps.

If you have `npm` on your machine, install the CLI with:

[source,shell]
----
npm install -g @enonic/cli
----

If not, there are https://developer.enonic.com/start[alternative ways to install the Enonic CLI].

Verify the installation by running `enonic -v`. This should print the version of the CLI. This tutorial expects version 4 or newer.

NOTE: You do not need to install Java or Gradle. The sandbox you create next bundles the Java runtime, and the CLI uses it when building your app.

== Create a sandbox

A _sandbox_ is a local developer instance of Enonic XP, with its own data and configuration. You can have several, each on its own XP version.

Create and start a sandbox called `{sandbox-name}` by running this command in your terminal:

[source,shell,{subs}]
----
enonic sandbox create {sandbox-name} -t essentials -f
----

The `essentials` template installs a set of applications from Enonic Market, including Content Studio and Guillotine, which you will meet in the coming chapters. The `-f` flag accepts the default answer to every prompt, which selects the most recent release of Enonic XP, and starts the sandbox.

NOTE: This tutorial is written for Enonic XP 8.1 and the versions of Content Studio and Guillotine that go with it. If the CLI offers you an older version, pick 8.1 or newer.

The sandbox prints a fair amount of output while it downloads XP, installs the applications and starts up. Once you see a line saying that Enonic XP has started, open http://localhost:8080[http://localhost:8080] in your browser. You should see the Enonic SDK welcome page, listing the sandbox's installed applications:

image::setup-sdk.png["The Enonic SDK welcome page for XP 8.1.0, with the Admin, APIs and VHosts cards, the installed applications Content Studio, Data Toolbox and Guillotine, and the sandbox's configuration files", width=1001]

Click btn:[Log In as Guest] to open the XP admin as the instance's super user. You should see something like this:

image::setup-home.jpg["The XP menu for the 101tutorial sandbox, with useful links on the left and tiles for Dashboard, Applications, Content Studio, Data toolbox and Users", width=1440]

This is the _XP menu_, the start page of the XP admin.
It lists the admin tools your user has access to.
Dashboard, Applications and Users come with the platform, and applications such as Content Studio add their own.
Once inside a tool, click the XP icon in the top right corner to return to the XP menu and switch to another tool.

In this tutorial, a path such as `XP menu` -> `Applications` means: open the XP menu, then click the Applications tile.

TIP: To stop the sandbox, press kbd:[ctrl-c] in its terminal. To start it again, run `enonic sandbox start {sandbox-name}`.

== Create an app

Almost everything in Enonic is an application: Content Studio is an app, Guillotine is an app, and the content types you are about to define live in an app of your own.

Creating an app from scratch can be daunting for any system you're not familiar with. To make things easier, Enonic provides https://market.enonic.com/starters[starters]. We'll use the "Vanilla" starter, which contains the bare minimum.

*Open a new terminal window*, leaving the sandbox running in the first one, and run this command:

[source,shell,{subs}]
----
enonic create {app-name-full} -r starter-vanilla -s {sandbox-name}
----

This uses `starter-vanilla` as a template, gives the app the name `{app-name-full}`, places the code in the folder `{app-name}`, and links the app to the `{sandbox-name}` sandbox.

TIP: You don't need to open the starter docs, so type `N` and press kbd:[Enter] if asked.

NOTE: App names matter. XP does not run two apps with the same name in a single instance, and the name acts as a namespace for everything the app defines, so it becomes part of the content type and GraphQL type names you will see later in this tutorial. If you choose a different name, substitute it wherever `{app-name-full}` appears.

The app folder contains a minimal Enonic application. The parts you will touch in this tutorial are:

.Essential app structure
[source,files]
----
src/
  main/
    resources/
      enonic.yaml // <1>
      cms/ // <2>
----

<1> The application descriptor, holding the app's title, description and vendor information.
<2> Where the content schemas you will create go.

NOTE: The other files in the folder, such as `build.gradle` and `gradle.properties`, belong to the build. You will not need to edit them in this tutorial.

== Build and deploy

Change to the app folder and start it in development mode:

[source,shell,{subs}]
----
cd {app-name}
enonic dev
----

This builds the app, deploys it to the `{sandbox-name}` sandbox, and then keeps watching the folder. Every time you save a file, the app is rebuilt and redeployed. Keep this command running in its own terminal while you follow the tutorial.

=== Change the app's title

Let's make a first change to the app, to see the development loop in action. Open the application descriptor, `{app-root}/enonic.yaml`, in your editor, and change the `title` and `description`:

.{app-root}/enonic.yaml
[source,yaml]
----
include::../{app-root}/enonic.yaml[]
----
<1> The starter calls the app "Vanilla Example". Give it a more descriptive title.
<2> Replace the stock description while you're at it.

Save the file, and watch the `enonic dev` terminal rebuild and redeploy. Revisit the Applications tool and you should see your new title.

=== Troubleshooting

If the app doesn't show up in the Applications tool, check the terminal running `enonic dev` for build errors first, then the sandbox terminal for errors from XP.

If the build works but nothing shows up, make sure the app is linked to the sandbox that is running. Run this command from the app folder and select `{sandbox-name}`:

[source,shell]
----
enonic project sandbox
----

For anything else, the https://developer.enonic.com/docs/enonic-cli[CLI documentation] covers every command and option, and the https://developer.enonic.com/docs/platform[platform documentation] covers the sandbox's configuration and ports.
